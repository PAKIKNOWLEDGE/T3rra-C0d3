> 视觉层是本项目最值钱的资产，整个项目围绕它转。**视觉层优先于后端存续**（`AGENTS.md` §二）。
> 本文是仓库里唯一的视觉权威。旧的 `visual-guide` / `design-contract` / `design-critique` 已归档到 [`archive/`](./archive/)。

## 2. 为什么旧范式失败（接手必读，防回潮）

1. **参照错了。** 旧 `ark-console` 取材于 ark-ui 这个 AI skill 对鹰角的二次演绎：近黑底、14% 细线、描边空心字、190px 停滞秒数。那不是游戏里每天被使用的界面。实机界面有四个共同点：实心块有分量；大字实心，本身就是按钮或读数；大数字是玩家关心的资源；文案是功能名词。演绎版这四点全没有。
2. **迁移只搬了颜色。** 2026-09-26 的第一、二刀只换 `<style>`，54 个 id 与旧骨架原样保留。结果是「旧骨架穿新衣服」：颜色对了，味道全丢。
   **教训：搬设计语言必须同时动三层**，缺一层就会走味：
   - 骨架（`index.html` 的构图）；
   - 组件形状与文案（`console.ts` 里建的 DOM 和写的字）；
   - 文档（本文），否则下一个人照着旧文档又做回去。
3. **「不造数」被执行成「只删不补」。** 样张里没有数据源的读数不搬是对的，但原位要换上装在同样重容器里的真事实，不能退回细线表格。

## 3. 硬约束（仅此四条，其余都可重构）

1. **不许悬空控件。** 满足任一条就算悬空，要么删掉，要么补上真作用：
   - 点了没有可观察结果；
   - 指向运行时不存在的概念（例如写死 `ASK`）；
   - 显示值不来自数据；
   - 永远禁用且没有可见原因；
   - 声称有尚未接上的能力。

   机检：`npm run check:app` + `app/ui-manifest.json`。
2. **不许造事实。** 屏上每个事实都要能追到一条事件或时钟。缺失时写 absence：`未告知` / `未报告` / `未建立` / `没有请求`。渲染层唯一的数据来源是 `app/src/view/derive.ts` 的 `ConsoleView`，外加 `SessionFacts`（进程与时钟事实）。
3. **无头浏览器禁用，不许声称看过渲染。** 交付界面时给出「可打开的路径」和 3–5 条「看什么」，由仓库主人目视验收。
4. **信道与平台边界。** `app/src/engine/transport.ts` 是唯一字节通道；UI 不认识事件词汇或引擎命令；视觉层不 import 引擎层（`npm run check:boundary`）。

## 5. 令牌与字体

- **数值只取正本**：全局令牌看 `tokens.json`（ARK 部分）；组件内部的字面色值（例如批准卡的 `#dfe0de`、`#c8c9c7`）以 `examples/ark.html` 为准，照抄，不新造色。`app/index.html` 的 `:root` 与正本的颜色令牌逐项一致（2026-09-26 脚本比对【实测】）。只有两处有意差异：
  - 多一个 `--gray-k`：未知 kind 工单用的中性灰，正本没有这一项；
  - `--f-sans` 少了 `"HMS"` 别名：产品里鸿蒙字体以本名注册，是同一份文件。
- **颜色只做一件事**：
  - 蓝：主操作 / 模式选中；
  - 黄：终端类工单、运行中；
  - 青：读取类工单；
  - 绿：修改类工单、就绪；
  - 橙：在等你；
  - 红：中止 / 失败 / 断链；
  - 浅色实面：被选中，或批准卡（全屏唯一）。
- **工单色条的依据**：来自引擎声明的 `kind`（`execute` / `read` / `edit` …）。`kind` 实测不可信（例如把目录列举报成 `read`），所以卡上**原文写出 kind**，颜色只是复述这个声明。卡名用 `title`。
- **字体**：正文 HarmonyOS Sans SC（随包）；数字与英文角标用 Bahnschrift SemiCondensed（Windows 自带）；等宽用 Cascadia Mono。见 `app/fonts/README.md`。

## 6. 文案

- **中文功能名词为主**：会话、指令、回复、工单、批准、中止、重启、就绪、运行中。英文只做 10px 大写角标（`WORK ORDERS`、`SESSION`）。
- **禁止判词与安慰**：STALLED / NEEDS YOU / SUSPENDED / NO SIGNAL；「卡住了吗」「它还在跑」。节奏判断用中性词：正常 / 偏慢 / 停滞，只在样本够了之后才写在右栏「节奏」里，不放大。
- **absence 用中文写**：未告知、未报告、未建立、没有请求、引擎尚未声明。
- 运行时词汇（模式名、option 值）只能来自数据，不能写死在外壳里（`check:app` 的禁止词表）。

## 7. 已知空白

- **没有可随包分发的窄斜体数字字体**。Bahnschrift 靠系统，mac/Linux 上会回退。
- **错误态版式**：断链、失败目前只有结局条这一种形态。引擎退出时没有专门的全屏态。
- **窄窗**：只有 1320 / 920 两档，是照搬正本写的。
- **长会话的站点卡**：一轮 30+ 个工单时，卡片网格会很长，还没有折叠。
- **工单类别映射**只覆盖 ACP 的 `ToolKind` 枚举，未知 kind 画成灰色「工具」。

## 8. 改视觉的流程

1. 先对照正本：[`demo/ark.html`](../demo/ark.html) 与 `DESIGN-LANGUAGE.md` §5.2 的组件表。
2. 想加一个读数，先问它能追到哪条事件。追不到就去 §4 的「不画」表登记，不要硬画。
3. 纯视觉改动只改 `app/index.html` 与 `app/src/ui/console.ts`。
   要**新增数据**（例如上下文圆环）就是契约变更，按 `rules.md` §五走：
   1. 先在 `docs/adapters/opencode-acp.md` 登记源码与报文证据；
   2. 再改 `app/src/contract/events.ts`（加事件）和 `app/src/engine/acp.ts`（把它从故意忽略的名单 `acp.ts:87` 里移出来，`usage_update` 目前就在那份名单上）；
   3. 然后改 `app/src/view/derive.ts`（加进 `ConsoleView` 与 `from` 溯源）；
   4. 最后让 `test/acp-coverage.test.ts` 保持通过。
4. `npm run check:all` 全绿。
5. 交付时给出 `npm run dev` → `http://localhost:5191/` 和 3–5 条「看什么」，写进 `status.md` 的验收表。

**交付自检**（取自正本 §11，逐条给结论）：

1. 去掉风格后还是好用的工具吗？
2. 面积最大的是要读的内容吗？
3. 选中 / 主操作 / 等你，是实面还是细线？
4. 每个签名元素都有指代吗？
5. 颜色都来自令牌，且只做一件事吗？
6. 大字是实心的，并且只给有意义的计数吗？
7. 文案是中文功能词吗？有没有判词或假数据？
8. 每个可点元素都有可观测结果吗？
